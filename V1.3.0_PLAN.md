## The direction (Dre's words, restated)

The next update focuses on the games on the platform. DHQ has a
website version, a Reddit version, and a PC version — TOW only has
Reddit. So the plan is: make sure the current games are publicly
accessible through the KOVA Platform Store, and a gamer can play
each game on web, PC, and Reddit — whichever is available for that
game.

## Two halves

### A. TOW gets a PC version (Gaming Team builds it)

TOW today: Reddit only (r/The_Open_World, v0.108.29; the Reddit
version profile + in-game art carry the OW explorer badge). DHQ
today: web (dispatch-hq.onrender.com), Reddit (0.56.0 submitted),
PC (itch desktop 0.4.1). The gap is TOW on PC — the Gaming Team

### B. KOVA Store: play on every platform that's available (OS Team)

The store catalog today carries ONE link per game (`download`).
That can't express "web + PC + Reddit". The catalog schema grows
to per-platform availability — **Dre's words for the three
slots (2026-11-14 ~01:04 CT): `web` / `file` / `reddit`**:

```json
"platforms": {
  "web": "https://dispatch-hq.onrender.com",
  "file": "https://avok-interactive.itch.io/dispatch-hq",
  "reddit": "https://www.reddit.com/r/DispatchHQ/"
}
```

- `web` — play in the browser (a URL).
- `file` — download the game file (the PC download).
- `reddit` — play on Reddit (the subreddit).

A platform key is present ONLY when that version actually exists
and is public — no dead buttons, no coming-soon placeholders.

Store UI (classic + beta): each listing shows one action per
available platform — "Play on Web", "Download" (the file),
"Play on Reddit" — and KOVA opens the right one (browser for
web/Reddit, download for the file). Games with a single platform
show a single action, as today.

**Uniform treatment (Dre, 2026-11-14 ~01:01 CT): all games are
treated the same way going forward** — Avok's own games and
dev-submitted games alike get the same per-platform listing
treatment. No special cases, no second-class listings.

### C. Dev submission becomes a real application (OS Team)

Phase A (v1.2.0) shipped a thin form that downloads a listing
JSON. Dre: that is not enough — the dev's game application needs
to be a REAL application for us to review, so we know what the
dev is trying to push: what, when, where, etc.

The application carries, at minimum:

- **What** — title, description, genre, art, the game itself
  (what it is, what you do in it).
- **Where** — every platform the game is on, with its link —
  web, file, reddit (Dre's three slots) — so the listing's
  per-platform treatment is filled in from the application.
- **When** — when the dev wants it listed / when it releases,
  so review and launch timing are known up front.
- **Who** — dev name + contact, so review questions have
  somewhere to go.

Review flow (unchanged rule): **listings are approved by BOTH
Melo and Dre** — an application is reviewed, then approved into
the catalog or declined with a reason. The catalog stays the
static JSON on the KOVA site, updated on approval.

**Open question — how the application reaches the reviewers.**
Options: (a) the in-app form produces a complete application the
dev sends to a review email (zero new infrastructure; review
happens from the inbox); (b) a hosted submission form on the
KOVA site (needs a receive endpoint — Wasmer static can't take
form posts alone). Recommendation: email first, hosted form
later if volume justifies it. Needs Dre's call on the review
address + the mechanism.

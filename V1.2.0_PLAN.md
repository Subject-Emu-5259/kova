## Goal

v1.2.0 makes KOVA feel like a platform that knows how you play: your
games get performance settings and real playtime, and the update
flow itself gets the polish the 1.1.1 saga earned. No backend, no
accounts, no commerce — everything still lives on your machine.

## Scope

### 1. Performance profiles (spec: PERF_PROFILES_SPEC.md)

The draft spec is already written and feasibility-checked. Per-game
profile gains a Performance section, shown only for games KOVA
launches locally (store/web titles launch through a URI — KOVA
controls nothing about their process, same honesty rule as launch
args):

- **Launch-arg presets** — engine-known argument sets (e.g. Source
  `+fps_max`, Unreal/Unity resolution + window flags) as one-tap
  additions on top of the existing free-text launch args. Labelled
  "sent to the game; the game decides what to honor."
- **Show FPS (macOS)** — a toggle that launches the game with
  `MTL_HUD_ENABLED=1` (Apple's Metal HUD: FPS, frame time, GPU
  metrics). Metal games only. Monitoring, not a cap.
- **Process priority** — Low / Normal / High. Minor knob, honest
  about its small effect.
- **Honest Mac limit, kept:** no FPS cap control on macOS — none
  exists for a launcher to use. The panel says so plainly instead
  of faking a slider.
- **Windows caps (gated, not promised):** NVIDIA driver cap via
  NVAPI and RTSS profiles are spec'd but need a Windows run-test
  and open-question answers before anyone builds them (§6 of the
  spec). They ship only when proven on a real Windows PC.
- **Config-file presets:** only for games on a verified allowlist,
  one title at a time — never a generic "set quality to Low."

State: new optional fields on the existing `GameProfile`, serde
defaults so old state files keep working.

### 2. Playtime tracking (deferred from 1.1.1)

v1.1.1 knows launch counts, not session lengths. v1.2.0 watches the
game process KOVA started and records the session when it exits:

- Per-game total playtime + last session length, stored in the
  profile.
- Profile view gains real stats: total hours played, most-played
  by time (not just launch count), recent sessions.
- Share card can carry total hours.
- Honest scope: only for games KOVA launches locally. Games
  launched outside KOVA (Steam directly, Finder) are invisible to
  it, and the UI says so.

### 3. Update flow polish (lessons from the 1.1.1 saga)

- **Real notes in the feed manifest.** The 1.1.1 manifest carried
  tauri-action's generic "See the release notes below." — the
  update prompt showed that instead of the real notes. From 1.2.0
  on, the feed publish step swaps the manifest's `notes` field
  for the release's real notes before deploying (signatures cover
  the artifact, not the manifest, so this is safe).
- **Feed publish checklist** written down in OTA_SPEC: copy the
  signed manifest byte-identical from the GitHub Release, swap
  notes, deploy, verify live version + decoded signature.
- **Signing-key backup reminder.** The 1.1.1 saga nearly stranded
  OTA on a forgotten password. The plan notes (not builds): Dre's
  key + password should live in his password manager. Nothing for
  Melo to hold — the key stays Dre's.

### 8. Game Store for devs — free games now, paid later (added 2026-11-13 on Dre's order)

Devs upload their games to KOVA's store. **Free games now; paid
games are future work, not this release** — no payments, checkout,
payouts, or pricing in v1.2.0.

Honest scope: a store where devs publish means a shared catalog,
and a shared catalog needs a server. KOVA has no backend today, so
this ships in phases:

- **Phase A (v1.2.0) — curated listings.** A dev submits a game
  page (title, art, description, download link) and KOVA lists it
  in the store. Downloads go to the dev's own hosting (itch.io,
  their site) — KOVA does not host game files yet. The catalog
  itself is a static JSON on the KOVA site, updated when a listing
  is approved — the same pattern as the OTA feed, no new backend.
  Listings are approved by BOTH Melo and Dre (Dre, 2026-11-13).
  Free games only.
- **Phase B (program) — KOVA-hosted uploads.** Devs upload game
  files to KOVA; KOVA stores and delivers them. Needs storage +
  bandwidth + a moderation/review flow + dev accounts. Spec'd and
  costed separately — not in v1.2.0.
- **Phase C (future) — paid games.** Stripe, payouts, tax,
  refunds, pricing. Dre already put this in the future; nothing
  here pre-builds it.

What v1.2.0 actually builds (Phase A): a Store browse in the app
that reads the catalog, game pages with art + description +
download link, a submission form (in-app or on the site), and the
approval step. Avok's own games (Dispatch HQ, The Open World)
become the first listings — the shelf grows into a store.

### 9. KOVA LIVE — Xbox Live, rethought (added 2026-11-13 on Dre's order)

Dre's words: "think of Xbox Live but in a whole new way and 1000
times better." This is a program, not a slice — it needs accounts,
a presence server, real-time messaging, moderation, and hosting.
v1.2.0 lays the groundwork; the full service is spec'd separately.

**The vision (draft pillars — Dre corrects what he doesn't want):**
- **Free online, no paywall.** Xbox Live's original sin was
  charging to play online. KOVA LIVE never charges for online
  play, friends, or parties.
- **One friends list across every store.** Your Steam, Epic, GOG,
  and itch friends in one place — KOVA already knows your library
  from all of them; LIVE knows your people from all of them.
- **Your data stays yours.** Local-first: your profile, playtime,
  and library live on your machine; you choose what LIVE sees.
  No ad profile, no selling attention.
- **Parties + voice built in.** Jump in a party with friends and
  talk while you play, no third app.
- **Achievements everywhere.** One achievement system that works
  across every store's games, not one per launcher.
- **Dev-friendly by default.** Indie devs publish free (§8) with
  no certification gauntlet — the store and LIVE are one system.

**Phases:**
- **Groundwork (v1.2.0):** your gamertag + local profile from
  1.1.1 becomes the KOVA LIVE identity seed — the tag you already
  have is your LIVE tag. Nothing online yet; the identity is
  portable by design (state export, §7).
- **Phase 1 (program):** accounts, friends, presence (online /
  in-game / what you're playing), messaging.
- **Phase 2 (program):** parties + voice, activity feeds,
  achievements.
- **Phase 3 (program):** multiplayer matchmaking, cloud saves.

**Honest cost:** accounts + real-time infra + moderation is the
biggest program KOVA has ever taken on — bigger than the store.
It gets its own spec, its own hosting decision, and Dre's go at
each phase. Nothing in v1.2.0 pretends LIVE is live.

### 10. More features, round two (added 2026-11-13 — Dre: "all of em i like all")

Melo pitched ten more ideas; Dre took all ten. All local-first
unless noted:

- **Big Picture mode** — a fullscreen TV mode, controller-only
  (Steam Big Picture style). Builds on the slice-6 controller
  nav, which Dre already rated 10/10.
- **Save-file backup** — KOVA finds your games' save files and

- **Cross-device sync through your own cloud** — profile + state

  server holding it.
- **Kids shelf** — a locked-down profile with only the games you

- **Local milestones** — badges on your profile for real play:
  100 launches, 10 games finished, 500 hours. No server, just
  your own history.
- **Game journal** — a quick note after a session: what you
  played, what you thought, kept per game.
- **One-tap launch modes** — "Quiet night" vs "Full power"
  presets that bundle your perf settings (§1) into a single tap.
- **Disk space view** — how much room each game takes, and what's
  eating your drive.
- **Menu-bar quick launch** — your recents in one click from the
  menu bar, no window needed.
- **Controller status in the Quick Panel** — what's connected and
  its battery level, right in the panel.

**Beta program mechanics:**
- Opt-in toggle in Settings ("Join the beta"). Off by default;
  the current UI stays the main UI for everyone not in the beta.
- When beta is on, a UI selector appears in Settings: Classic /
  Beta. Switching is instant (the shell reloads); the choice is
  stored in state and remembered across launches.
- Beta surfaces carry a beta badge. Beta users get upcoming
  features first, behind feature flags in state — the beta is
  the early-access channel for the public platform update.
- Feedback: beta users get a feedback entry in Settings (local
  note for now — no backend to send it to; Dre's call on where
  feedback goes when LIVE lands).

**Beta UI / profile customization features (beta first, graduate
to main later):**
- Theme + accent choices for the beta shell — four accents:
  cyan, raspberry, amber, emerald (§11).
- Profile banner / cover image on the Profile view.
- Layout density (comfortable / compact).
- Custom shelf order (drag your shelves into your order).
- The beta UI is where customization ships first; what proves
  out graduates to the main UI in a later release.

**Architecture (honest):** the beta UI is a second frontend shell
(`app/src/beta/`) sharing the same Tauri commands and the same
`kova-state.json` — one backend, two shells. The app loads the
chosen shell at startup. No new Rust dependencies for the shell
itself; customization state lives in the existing profile.

**Gate (standing rule):** `inspect.mjs --app` on every beta
